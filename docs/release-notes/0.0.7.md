The fourth update to Roga, with a way to report an issue from the Help menu, a warning when git can't list a worktree's files, and a Codex check in Settings that no longer times out. Roga now needs git 2.45 or later.

## What's new

- **Report an issue.** Help › Report an Issue… replaces Roga Help, which only said there was no help. A dialog says that a new issue for Roga opens on GitHub in your browser, that nothing is sent until you submit it there, and that issues are public. The issue starts with the versions of Roga, macOS and git, and nothing about your repositories.
- **Worktrees git can't list.** When `git status` fails in a worktree, because its index is damaged, its changes are too many to read, or it's a partial clone that would have to download, Roga says so instead of showing the worktree as clean. The uncommitted row stays and says "Can't list uncommitted files" in red, and selecting it shows git's message. The sidebar shows an orange triangle in place of the count, with git's message in its tooltip, and Hard in the reset dialog is red, with a note.

## Smaller changes

- After a push or a pull, the house stays beside **Pushed** or **Pulled** until the words go 3 seconds later, and the counts come back as it leaves. A quick push no longer loses its house the moment it finishes.
- Settings › Agents no longer says that checking Codex's hooks timed out. Roga asks Codex only about Roga's own marketplace, so Codex doesn't download OpenAI's plugin catalog before it answers.
- Roga needs git 2.45 or later, up from 2.44, so that a partial clone in the sidebar never downloads anything just because Roga opened it. The setup screen says so when your git is older.
- Roga uses Codex 0.137.0 or later, up from 0.131.0, because earlier versions can't list their plugins as JSON. Settings shows an older Codex as too old.
